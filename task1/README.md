# 任务一：植物幼苗分类

## 任务与数据

给定植物幼苗的俯拍图像，判断它属于 5 个物种中的哪一类：Black-grass、Common wheat、Loose Silky-bent、Scentless Mayweed、Sugar beet。训练集 500 张，每类 100 张，类别均衡；测试集 378 张，无标签。提交文件为 ID 与 Category 两列，共 378 行，评价指标是 Micro F1。

图片格式为 PNG，多数是 RGB，长边从 49 到 2840 像素，跨度很大。所有图都拍在同一批托盘、土壤和砾石背景上，背景的颜色和纹理在不同类别之间有差别。这一特点决定了后面的增强策略，强增强会破坏背景信息，反而掉分。

## 方法

**训练阶段**（`code/01_训练/plant_classification.ipynb`）

- 骨干用 ImageNet-22k 预训练的 ConvNeXt、Swin Transformer、EfficientNet，替换分类头后微调。按骨干和输入分辨率分成 5 批，共 15 个模型。
- 所有图片先转 RGB，缩放到指定分辨率，再用 ImageNet 均值方差归一化。
- 训练用弱增强：RandomResizedCrop 的 scale 取 (0.7, 1.0)、ratio 取 (0.85, 1.18)，水平与竖直翻转概率各 0.5（叶片没有固定朝向），颜色抖动只做轻的，亮度、对比度、饱和度幅度 0.1，色调 0.02。RandAugment、RandomErasing、MixUp、CutMix 都没有用。
- 验证集和测试集先放大 1.14 倍再中心裁剪，保证每次评估结果一致。
- 每轮迭代步数只有 13 到 25 步，EMA 衰减用 0.995。每轮同时看原始权重和 EMA 权重，保存验证集 F1 较高的那一组。
- 每个模型做 5 折交叉验证，500 张样本每张恰好被预测一次，拼成完整的折外预测（OOF）。OOF 只用来选模型和算融合权重，测试集预测只用于最后提交。
- 推理时做 D4 对称 TTA，4 个旋转角度与水平翻转组合成 8 路，对 8 路概率取平均。

**融合阶段**（`code/02_融合/reproduce.py`）

先在 OOF 上比较等权平均、概率几何平均、多数投票，三者分别是 0.9340、0.9340、0.9400，都低于最强单模型。原因是模型强弱差距大，等权会被弱的拖下来，所以改用贪心前向选择：从空集开始，每一步从 15 个模型里挑一个加进来使当前 OOF Micro F1 最大，共走 25 步，允许重复选。得到的权重原样作用到测试集概率上，加权平均后取 argmax。测试集不参与任何选择。

## 结果

| 项目 | 数值 |
|---|---|
| 最优单模型 OOF Micro F1（Swin-Tiny，run5） | 0.9500 |
| Swin-Small（run2）、ConvNeXt-Tiny（run6） | 均为 0.9420 |
| EfficientNet-B3（run2），15 个模型里最低 | 0.8620 |
| 等权平均 | 0.9340 |
| 概率几何平均 | 0.9340 |
| 多数投票 | 0.9400 |
| 贪心加权融合 OOF Micro F1 | 0.9600 |
| 嵌套交叉验证（外层评估融合流程） | 0.9520 |
| 最终配置包含的模型与权重 | Swin-Small 17、Swin-Tiny 7、EfficientNet-B3 1 |

15 个基模型的 OOF 大多落在 0.86 到 0.95 之间。贪心融合比最强单模型高 1 个百分点，15 个模型里只有 3 个被选中，其余 12 个在过程中被淘汰，因为弱模型加进来会拉低整体。

贪心是在 OOF 上选的，存在选择偏差。嵌套交叉验证在 4/5 的训练样本上选权重，在剩下的 1/5 上评估，5 折平均 0.9520，比样本内的 0.9600 低约 0.8 个百分点。有一点乐观偏差，但结论成立。

平台公榜与私榜成绩均为 0.9708，公榜排名 20/80，私榜排名 20/80。平台测试集是 378 张独立图片，与 500 张训练图上的 OOF 口径不同，两个数字不能直接比较。

同类问题还有一个例子。Stacking 的元分类器在 OOF 上的样本内准确率有 0.9780，看着提升很大，嵌套交叉验证只有 0.9320，差了 4.6 个百分点，60 维特征对 500 个样本基本是记住了训练集，因此没有采用。

## 文件说明

```
code/01_训练/plant_classification.ipynb   单模型训练与 5 折 OOF 生成（默认 run5）
code/02_融合/reproduce.py                 贪心权重搜索、提交生成与格式校验
config/selected_config.json               融合后的模型权重、类别表与 OOF 分数
inputs/train_labels.csv                   训练集文件名、类别与标签（500 行）
inputs/test_ids.txt                       测试集文件名顺序（378 行）
inputs/oof/*.npy                          15 个模型的折外概率（500×5）
inputs/test/*.npy                         15 个模型的测试概率（378×5）
submission_template_official.csv          官方提交模板
submission.csv                            最终提交
```

`inputs/` 下的概率数组每个约 10 KB，是从训练过程直接导出的中间结果，用来在不重训模型的情况下复现融合与提交。

## 运行方式

```bash
# 复现最终提交
python3 code/02_融合/reproduce.py

# 校验生成的提交与仓库内的 submission.csv 是否一致
python3 code/02_融合/reproduce.py --out /tmp/sub.csv --verify
```

复现脚本生成的文件 MD5 为 `af974f12368900c95a5126236b051805`，与仓库内的 `submission.csv` 一致。

重训单模型需要把比赛图像放到 notebook 中约定的目录，然后执行训练单元和 OOF 导出单元。notebook 默认是 run5，改一下输入分辨率和骨干列表即可复现其余批次。

## 注意

原始图像数据没有放入仓库。`reproduce.py` 只依赖 `inputs/` 下的概率数组和 `config/selected_config.json`，因此融合与提交这两步不需要图像即可完整复现。
