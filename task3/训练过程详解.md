# 任务三：中心凹（黄斑）检测定位 —— 训练过程详解

> 日期：2026-10-22
> 最终提交：`submission/submission.csv`（Kaggle ref 57480074）
> 公榜 RMSE 11.99623

---

## 1. 任务与数据

- **任务**：输入一张眼底图像，输出黄斑中央凹（fovea）在原图像素坐标系下的坐标 `(Fovea_X, Fovea_Y)`；若不可见则输出 `(0,0)`（本数据集全部可见）。
- **训练集**：80 张（0001–0080），另附 `train_location/*.xml` 黄斑框标注。
- **测试集**：20 张（0081–0100）。
- **分辨率**：2992×2000（训练 75 张、测试 19 张）、1956×1934（训练 5 张、测试 1 张）。
- **评价**：提交按 X/Y 拆成两行（40 行），指标为 RMSE：
  `RMSE = sqrt( (Σ(ŷ_i − y_i)² + Σ(x̂_i − x_i)²) / (2N) )`
  公榜取其中 20 行评分。

**数据特点**：
- 黄斑在图像中表现为视盘颞侧约 2–2.5 个视盘直径处的暗区；
- 不同图像色彩差异大（暗红、过曝发白、偏绿等）；
- 少量图像（86、87 等）的标注点偏离暗区中心，存在标注歧义。

---

## 2. 总体技术路线（演进过程）

整体走的是 **单阶段热图回归（heatmap regression）** 路线，关键演进：

1. **整图 MSE 回归高斯热图** → 全局信号太弱，验证 RMSE 卡在 480+，放弃；
2. **空间 softmax 交叉熵（CE）+ 高斯软标签** → 10 轮验证即 17.5px，是转折点；
3. 5 折交叉验证 + 多模型集成 + 多尺度推理 → 公榜 13.65；
4. **视盘锚点通道（第 4 输入通道）** → 公榜 11.59；
5. 通过同折多随机种子集成，最终提交公榜 **11.99623**。

最终方案一句话：
> 用 ImageNet 预训练的 ResNet18 提取特征，FPN 融合多尺度特征输出 stride=4 的黄斑热图；
> 以"空间 softmax + 高斯软标签"作为主损失、全局 soft-argmax 坐标 L1 作为辅助损失；
> 输入额外拼接一路以视盘中心为中心的高斯通道；5 折 + 同折多种子集成，热图峰值取亚像素质心，
> 多尺度（512/384）推理后按坐标中位数融合。

## 3. 数据预处理与增强

### 3.1 预处理
- 读取 RGB，直接缩放到 **512×512**（训练时先缓存 1024×1024，再用仿射变换裁到 512）；
- 坐标一律使用**归一化坐标**（x/W, y/H），因此两种分辨率可以统一处理；
- 图像按 ImageNet 均值/方差归一化；
- **视盘通道**（最终模型）：用经典检测器求视盘中心，生成一张以该点为中心的高斯热斑（σ=10px@512），
  作为第 4 个输入通道。

### 3.2 数据增强（训练时）
| 类型 | 参数 |
|---|---|
| 随机旋转 | ±15° |
| 随机缩放 | 0.85–1.25 |
| 随机平移 | ±7% |
| 水平翻转 | p=0.5 |
| 亮度/对比度 | 对比度 ×0.85–1.15，亮度 ±0.08 |
| Gamma | 0.8–1.25 |
| 通道增益 | 每通道 ×0.95–1.05 |
| 高斯模糊 | p=0.15，σ 0.5–1.5 |
| 噪声 | p=0.1，σ=0.01 |
| CLAHE | p=0.5（部分实验） |

增强后的 GT 坐标用同一个仿射矩阵变换，保证标签与图像严格对齐（已可视化验证）。
坐标越界（超出图像 2%）时重采样仿射参数，最多 5 次。

## 4. 模型结构

### 4.1 主模型：ResNet18 + FPN 热图回归（最终采用）

```
输入 4×512×512（RGB + 视盘高斯通道）
 └─ ResNet18 stem + layer1（ImageNet 预训练，冻结，BN 保持 eval）
     ├─ layer1 (/4, 64ch)  ──1×1 conv→96──┐
     ├─ layer2 (/8, 128ch) ──1×1 conv→96──┤ 逐级上采样相加
     ├─ layer3 (/16,256ch) ──1×1 conv→96──┤
     └─ layer4 (/32,512ch) ──1×1 conv→96──┘
 └─ 3×3 conv + BN + ReLU（96ch）
 └─ 1×1 conv → 1 通道热图（stride=4，512 输入对应 128×128）
```

- 骨干：`torchvision.models.resnet18(weights='IMAGENET1K_V1')`；
- **冻结 stem + layer1**（约一半参数不更新，BN 统计量固定），只训练 layer2–4 与 FPN 头；
- 4 通道版本：把 conv1 换成 4 输入通道，第 4 通道权重初始化为 RGB 三通道权重的均值；
- 输出为**未归一化的 logits**，推理时做空间 softmax。

### 4.2 其他尝试过的模型
| 模型 | 说明 | 结果 |
|---|---|---|
| ResNet34 + FPN | 更深骨干 | fold0 验证 15.0，与 R18 的 15.3 持平 |
| width=128 解码器 | 更宽 FPN | 验证 14.79，但困难图更差 |
| 直接坐标回归 | ResNet18 + GAP + FC(2) | 验证 134px，严重不足 |
| 二阶精修模型 | 原图 512 裁剪→再回归偏移 | GT 居中验证 28px，组合后变差 |
| 偏移量热图 | 预测"相对视盘的偏移" | 验证 96px，失败 |

## 5. 损失函数（关键设计）

### 5.1 主损失：空间 softmax 交叉熵 + 高斯软标签
把 128×128 热图看作 **16384 类分类问题**，目标是用 GT 处的高斯分布归一化后的软标签：

```
q(i,j) = Gaussian(σ=1.2 cell) / Σ q
logp   = log_softmax(logits.flatten(1))
L_ce   = −Σ q·logp
```

- 与 MSE 相比，softmax 的分母让**背景被显式建模**，梯度能覆盖全图，解决"MSE 只优化局部、全局位置学不到"的问题；
- 初期用 MSE 时验证 RMSE 480+，换 CE 后 10 轮即 17.5px。

### 5.2 辅助损失：全局 soft-argmax 坐标 L1
```
p  = softmax(logits)
x̂  = Σ p(i,j)·i ,  ŷ = Σ p(i,j)·j
L_xy = |x̂ − x_gt| + |ŷ − y_gt|     （单位：cell）
```
- 直接对坐标施加监督，抑制峰值漂移；
- 总损失：`L = L_ce + 0.01·L_xy`（实验过 0.03 / 0.1，无明显提升）。

### 5.3 推理时的峰值提取
```
softmax → 全局 argmax 找到峰值 cell → 在峰值周围 13×13 窗口内
用 relu(p)^2 作为权重求加权质心 → 亚像素坐标
```
- 比单纯 argmax 稳定，比全图期望更鲁棒（不受远处小概率质量影响）。

## 6. 训练配置与流程

### 6.1 优化器与调度
| 项目 | 设置 |
|---|---|
| 优化器 | AdamW |
| 学习率 | 编码器 2e-4，FPN 头 1e-3 |
| 权重衰减 | 1e-4 |
| 调度 | 3 epoch warmup + cosine 退火到 0 |
| Batch size | 8 |
| Epochs | 60（单折/全量均 60） |
| 梯度裁剪 | max_norm=5.0 |
| 输入尺寸 | 512×512 |
| 硬件 | 16 核 CPU（无 GPU），ResNet18@512 约 15 秒/epoch（64 张） |

### 6.2 交叉验证划分
- `StratifiedKFold(n_splits=5, shuffle=True, random_state=42)`；
- **按图像分辨率分层**：5 张 1956×1934 的图平均分到 5 折（每折验证集恰好 1 张）；
- 每折 64 张训练、16 张验证；
- 模型选择：每 5 个 epoch 在验证集上算 RMSE，保存最优 checkpoint（best.pt）。

### 6.3 训练流程（单折）
1. 预缩放全部图像到 1024×1024 缓存在内存（约 300MB）；
2. DataLoader（4 workers）在线做仿射 + 颜色增强，生成 512×512 输入与 128×128 高斯热图；
3. 前向 → 计算 CE + 坐标损失 → 反向 → 更新；
4. 每 5 轮验证，保存最优；
5. 训练结束保存 last.pt / best.pt 与参数。

### 6.4 集成的训练策略
- **5 折模型**：每折训练一个模型（共 5 个），覆盖不同数据子集；
- **全量模型**：`--fold -1` 用全部 80 张训练（无验证，取最终 epoch）；
- **同折多种子**：固定 fold0 的划分，仅改变增强随机种子（`--aug_seed`），训练多个模型；
- 所有模型的参数（backbone、width、size、disc_ch 等）保存在 checkpoint 的 `args` 中，推理时自动读取。

## 7. 推理与集成

### 7.1 单模型推理
1. 图像缩放到 512×512（多尺度时分别 512、384）；
2. 视盘通道按模型是否 4 通道自动拼接；
3. 前向得到热图 → softmax → 峰值 + 局部质心 → 归一化坐标；
4. 多尺度预测在归一化坐标下平均。

### 7.2 多模型集成
- 每个模型输出一组坐标（多尺度平均）；
- 跨模型取 **坐标中位数**（对个别模型的离群预测稳健）；
- 最后映射回原图坐标：`x = ux·W, y = uy·H`。

### 7.3 被验证无效/有害的推理技巧
| 技巧 | 结论 |
|---|---|
| 水平翻转 TTA | 困难图上预测剧烈漂移（fold1 23→59px），有害 |
| 旋转 TTA | 同样不稳定，有害 |
| 颜色抖动 TTA | 几乎无变化 |
| 热图级融合 | 与坐标中位数相当（CV 18.80 vs 18.87），未采用 |
| 视盘锚点收缩 / 距离门控 | CV 上严重变差，放弃 |

## 8. 视盘锚点通道（关键改进）

### 8.1 动机
黄斑与视盘有稳定的解剖关系（颞侧、约 2–2.5 个视盘直径、略低于视盘中心）。
在过曝/低对比度图像（如 0086）上，CNN 容易把暗区中心当成黄斑，而视盘仍然清晰可见。

### 8.2 视盘检测（经典方法）
1. 灰度图高斯模糊（σ=7）；
2. 在眼底掩膜内取 99 分位阈值，得最亮连通域；
3. 取最大连通域的质心作为视盘中心（归一化坐标）；
4. 对全部 100 张图预计算，存为 `disc_centers.csv`。

### 8.3 通道构造
在 512×512 输入上生成以视盘为中心、σ=10px 的二维高斯热斑，作为第 4 通道；
数据增强时与图像一起做同样仿射变换；多尺度推理时 σ 按比例缩放。

### 8.4 效果
- 单模型（fold0）：公榜 **11.59**（此前最好 13.65）；
- 同折多随机种子可进一步稳定困难图上的预测。

## 10. 误差分析

- RMSE 只有 20 行，一两张难图的平方误差就会主导整体分数。公榜 11.99 与交叉验证 19.7 的差距主要来自取样不同，不是模型退化。
- 困难图集中在三类：视盘边缘附近的图、带病灶的图、黄斑过曝或对比度偏低的图。这些图上同一模型的不同随机种子会给出相差几十像素的结果，集成取坐标中位数就是为了压住这种离散。
- 训练集标注点基本落在暗区加权质心的邻域（中位偏差 9px），但不是每张图都如此，个别图的人工标注落在暗区边缘。这类样本本质上是标注歧义，热图回归学到的是暗区形状，难以复现标注者的选择。
- 视盘锚定在交叉验证上的 RMSE 约 70，远差于卷积模型的 20 上下。它在个别困难图上可能更接近标注点，但没有可靠的切换判据，硬切会让平均误差变差，因此没有采用。
- 综合来看，11 到 12 之间的波动主要是随机性，继续堆同构模型收益很小。

## 13. 经验总结

1. **损失函数比模型结构更关键**：整图 MSE → 空间 softmax CE 是全场最大的一次跃升（480+ → 17.5）。
2. **小样本任务要冻结浅层**：冻结 stem+layer1 既省算力又抑制过拟合，配合强几何/颜色增强效果最好。
3. **集成要选"稳"的聚合**：坐标中位数比均值/热图融合更抗离群；翻转、旋转 TTA 在困难图上反而有害。
4. **引入解剖先验有效**：视盘锚点通道让公榜从 13.65 降到 11.59，是第二大改进。
5. **RMSE 由少数难样本主导**：10 张图的榜单里只要 1 张差 50px，RMSE 就会被抬到 ~15；
   因此误差分析（逐行、逐图）比盲目调参更重要。
6. **警惕标注歧义**：当所有模型都收敛到同一错误位置时，问题往往不在模型，而在标注约定/歧义，
   此时继续堆模型或做"逐图挑模型"没有意义，也容易滑向对测试集的过拟合。

## 14. 为什么本次实验直接使用本地 CPU，而不是 Kaggle GPU

### 14.1 结论先行
本次任务的数据量只有 **80 张训练图 / 20 张测试图**，模型是 **ResNet18 级别（约 1100 万参数，且一半冻结）**，
真正的瓶颈是**数据量与标注歧义**，不是算力。因此使用本地 16 核 CPU 训练是更高效、更可控的选择；
GPU 即使快 5–10 倍，也不会提高精度，反而会引入额外的工程成本。Kaggle 平台在本项目中只用于**提交**，
不用于训练。

### 14.2 算力需求实测
在 16 核 CPU、PyTorch CPU 版（无 GPU）上：

| 项目 | 实测耗时 |
|---|---|
| ResNet18 @512，batch 8，一次前向+反向 | 约 1.7 秒 |
| 单折（64 张 × 60 epochs） | 约 15 分钟 |
| 全量模型（80 张 × 60 epochs） | 约 19–25 分钟 |
| 最终提交所需模型（5 折 + 2 个同折种子，共 7 个） | 约 1.5–1.8 小时 |
| 全部探索性实验（约 30 个模型） | 约 1.5 天（含分析与可视化） |

单张图一次前向+反向约 0.24 秒；整个最终集成不到 2 小时即可训完。这个量级完全在本地 CPU 的舒适区内。

### 14.3 为什么 GPU 不会提升精度
我们实际做过"用更多算力"的对照实验，结果都不升反降：

| 更多算力的尝试 | 结果 |
|---|---|
| ResNet34（更深骨干） | fold0 验证 15.0，与 ResNet18 的 15.3 持平 |
| width=128 解码器 | 验证 14.79，但困难图反而更差 |
| 768×768 输入（约 2.25 倍计算量） | 验证 20.0，明显变差（小样本更易过拟合） |
| 640 输入 | 无提升 |

原因是**数据量只有 80 张**：模型容量和分辨率再提高，只会加剧过拟合；
真正的收益来自损失函数（MSE→空间 softmax CE）、集成策略和视盘先验，这些都是"想法"而非"算力"。

### 14.4 使用 Kaggle GPU 的工程成本
1. **数据与代码搬运**：需要把 80 张训练图 + 20 张测试图（约 100MB）和代码上传到 Kaggle Dataset/Notebook，
   每轮实验还要同步修改；本地则是直接读写文件。
2. **会话与配额限制**：Kaggle Notebook 单次会话有时长上限（GPU 一般 9 小时/天、每周 30 小时 GPU 配额），
   断开后需要重新加载；本地可以连续跑、随时打断续训。
3. **迭代效率**：本项目的迭代以"改损失/改增强/看可视化/逐行误差分析"为主，
   本地可以直接用 Python 脚本 + OpenCV 可视化，一轮分析几十秒；
   放到 Notebook 里反而更慢。
4. **可复现与调试**：本地固定随机种子、checkpoint、日志文件都在手边；GPU 环境的 CUDA/驱动版本差异
   也可能带来数值差异。
5. **提交本身不需要 GPU**：Kaggle 提交只是上传一个 CSV，用 API 即可完成（本项目还遇到了
   `www.googleapis.com` 上传被网络限制的问题，本地脚本通过 `storage.googleapis.com` 绕过）。

### 14.5 什么时候才值得上 GPU
如果满足以下任一条件，GPU 才是必需的：
- 训练集达到 10^4–10^5 张（例如公开眼底数据集规模）；
- 需要 1024 以上分辨率 + 更重的骨干（ResNet50/HRNet/ViT）做端到端训练；
- 需要大量超参数搜索或大模型预训练/微调。

在本任务（80 张图、单阶段热图回归、ResNet18）下，本地 CPU 已经足够，且更省事、更可控。
